# M01 — Make cards from notes, on a generated vault (US-005)

Part of the [manual checks](../manual-checks.md).

**When:** after US-008 (the plugin can be installed), and after any change to
the commands, the runner, the deck note's links or the output folder rules.

**Needs:** Obsidian desktop and a PDF viewer. Prepared by the developer
(SCAR-012, SCAR-018): the vault generated with `node
--experimental-strip-types tests/fixtures/generate-vault.ts <new folder>`
(it writes only into a folder that does not exist; invented notes, SCAR-035);
a checksum list of every file in it taken **before** the check
(`find <vault> -type f | sort | xargs shasum -a 256 > before.txt`); the plugin
build installed in that vault with its own version, `main.js`,
`manifest.json` and `styles.css` byte-identical to the fresh build (checksums
in the hand-over note); an empty output folder **outside** the vault
(`m01-out`); the plugin's settings written by hand into its `data.json`
(there is no settings screen before US-007): kind rules `Skills` -> skill and
`Spells` -> spell, output folder the full path of `m01-out`; the settings
file's content in the hand-over note. The developer waits for the tester's
"go" after each run (the output folder holds the files of one run at a time).

**Expected version:** the version in the hand-over note (first line of the
plugin's entry in Settings, Community plugins). If it differs, stop: the wrong
build is installed. Restart Obsidian once so the build is loaded.

**Known limitations (SCAR-024, SCAR-032, SCAR-045):** the tests use a
stand-in for Obsidian's link lookup; **steps 7 and 8 measure the real one** and
the tester reports what they see (the predictions below are the stand-in's).
Not measured: runs on Windows; a vault on a network drive. The text is
invented.

Read the PDF at reading size (100 %, SCAR-025) and zoom in on the card edges.

## Steps

1. Open the vault. Settings, Community plugins: the plugin is on and its
   version is the expected one.
2. Open `Decks/Opening Deck.md`. Open the command palette and run `Create
   cards from this deck note`. **Expected:** a notice `6 cards on 1 page, 6
   warnings. Written to <the full path of m01-out>` (the warning count may
   differ by the answers of steps 7 and 8; note it).
3. In `m01-out` there are exactly two files: `Opening Deck cards.pdf` and
   `Opening Deck cards warnings.md`. Open the PDF: **one A4 page, six cards in
   rows of three**, in this order: `Reed Sweep`, `Reed Whisper`, `Guard
   Stance`, the note answered for `dup`, `Stone Skin`, `Reed Sweep`. The
   first card has two tags, the title, a row `Time: action · Type: attack ·
   Requires: Basket Knots`, the text with one bold and one italic word, a
   bullet list of two items, and **no picture**. The spell cards have no row.
   Cut marks sit in the margins. Nothing is cut at a card's edge.
4. Open the warnings file. **Expected, in this order:** a heading `# Opening
   Deck cards: warnings`, then `DECK_LINK_MISSING` for `Gone Note`, a warning
   for `Skills` (a folder: `DECK_LINK_NOT_A_NOTE` or `DECK_LINK_MISSING`:
   **report which**), `DECK_LINK_AMBIGUOUS` for `dup` (**report the path it
   says it used**), `CARD_KIND_UNKNOWN` for `Misc/Loose.md`, and
   `SKILL_IMAGE_OMITTED` for `Skills/Combat/Reed Sweep.md` twice.
5. Run the command again. **Expected:** a question that names both files, with
   the buttons `Replace` and `Cancel`; **the focus is on `Cancel`**. Press
   Escape: nothing changes (the two files keep their time stamps). Run again,
   press Enter at once (it is on `Cancel`): the same. Run again, click `Replace`:
   the files are written again and the notice appears.
6. In the file explorer, right-click the folder `Skills/Combat` and choose
   `Create cards`. **Expected:** `Combat cards.pdf` and `Combat cards
   warnings.md` appear (the question of step 5 does not appear: they are new);
   the PDF has the three notes of that folder, sorted without case (`dup`,
   `Guard Stance`, `Reed Sweep`). Select two notes with the Shift key and
   choose `Create cards`: the files are named `Cards cards.pdf` and `Cards
   cards warnings.md`.
7. **The real link lookup, measured.** For each link of the deck note, read
   from the PDF and the warnings file what Obsidian answered, and fill the
   table in your report: `[[Reed Sweep]]` (a bare name), `[[Reed
   Whisper|the whisper]]` (an alias), `[[Guard Stance#Notes]]` (a heading),
   `[[Skills]]` (a folder), `[[dup]]` (two notes with this name: **which
   one?**), `[the stone spell](../Spells/Stone%20Skin.md)` (a relative path).
8. Change `Decks/Opening Deck.md` in Obsidian: add the line `- [[Combat/dup]]`
   and `- [[General/dup]]`; run again and report which notes they gave. (Do not
   change any other file.)
9. **Refusals.** In `data.json` (close the settings first, restart if the
   plugin needs it) set the output folder to empty: the command shows a notice
   that **names the output folder**, and nothing is read or written. Set it
   to `~/cards`: refused with the value in the message. Set it to the vault's
   own folder: refused. Set it to a path of a file: refused. Set the kind rules
   to none: the notice names the kind rules. Restore the settings.
10. Two runs at once: run the command and, while the notice has not come,
    run it again: the second shows `A run of cards is already in progress`.
    (If a run is too fast to try, say so.)
11. **The vault is unchanged.** Take the checksum list again and compare:
    `find <vault> -type f | sort | xargs shasum -a 256 > after.txt; diff
    before.txt after.txt` (the step 8 edit and the plugin's own `data.json` and
    the step 9 settings are the only differences allowed; list them). Report
    the result of the `diff`.
12. Is anything missing, odd or ugly that this list did not ask about? Report
    it even if it seems unrelated (SCAR-015): the cards, the notices, the
    question, the file names.

**Then, once, on the author's real vault** (after the steps above passed): the
settings are the author's own (kind rules for the real folders, an output
folder outside the vault); run the command from one deck note and from one
folder; only look at the PDF and the warnings file. The vault is only read:
take the checksum list before and after and report that they are equal.

**The developer's undo (SCAR-018):** the scratch vault and `m01-out` are
deleted; nothing outside them was changed. The real vault is not changed by
this plugin.
