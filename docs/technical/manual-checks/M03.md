# M03 — Which way opens the system's folder dialog? The spike (US-007 G1)

Part of the [manual checks](../manual-checks.md).

**When:** before US-007's story is Ready (SCAR-045: the approach is measured in the
author's Obsidian before the story builds on it), and again if Obsidian or its Electron
changes in a way that could matter.

**Needs:** Obsidian desktop on the author's machine, the scratch vault with the spike build
installed (a test build with its own version, never published). Prepared by the developer
(SCAR-012): the build installed with the checksums of the installed files equal to the fresh
build's (hand-over note), two folders to pick: `spikes/m01-out` (holds files) and
`spikes/m03-empty` (an empty folder, outside the vault), and the console's **Preserve log**
advice. Restart Obsidian so the build is loaded.

**Expected version:** the version in the hand-over note (the plugin's entry in Settings,
Community plugins). If it differs, stop: the wrong build is installed.

**What the build has:** four developer commands, `Spike: pick a folder, A` to `D`. Each
tries one way to open the system's folder dialog, shows a notice with one line and logs it
(`GCC spike ...`) with the versions of Electron and Chrome. They change nothing.

| Candidate | The way |
|---|---|
| A | `require('electron').remote.dialog.showOpenDialog({properties: ['openDirectory']})` |
| B | `require('@electron/remote').dialog.showOpenDialog(...)` |
| C | an `<input type=file webkitdirectory>`; reports `file.path`, `webkitRelativePath` and `electron.webUtils.getPathForFile` |
| D | `window.showDirectoryPicker()` (answers a folder *name*, no path) |

**Decided before the run (SCAR-032, SCAR-020):** the way the plugin uses is the first of A,
B, C that answers an **absolute folder path** for a folder with files **and** for the empty
folder, and reports a cancel without an error. D is a fallback only if it gives a path
(it should not). If only a way that cannot give a path for an empty folder works (C needs a
file in the folder to learn the folder), the story offers that way **and** says so in the
tab, next to the text field. If no way works, the output folder stays a text field and
decision 1 of the author is renegotiated. No way is chosen from a guess.

## Steps

1. Open the scratch vault. Settings, Community plugins: the version is the expected one.
   Open the developer console, tick **Preserve log**.
2. Run `Spike: pick a folder, A`. **Report** what happens: a system dialog or not, the
   notice, the console line. If a dialog opens, choose `spikes/m01-out` and confirm. Run it
   again and choose `spikes/m03-empty`. Run it a third time and cancel the dialog.
3. The same for `B`.
4. The same for `C` (Chromium may ask whether to upload the files: confirm; report that
   it asked). For the empty folder, report what the notice says.
5. The same for `D` (a permission prompt may appear; report it).
6. Copy the lines from the console (filter `GCC spike`), which include the Electron and
   Chrome versions.
7. Is anything odd (a dialog behind the window, a freeze, a second dialog)? Report it.

## Results (the author's run of 2026-11-12, build `0.1.0-m01.4`)

Versions (the console line): **Electron 43.8.4, Chrome 150.0.7871.250, Node 24.22.1,
Obsidian 1.15.0**; machine: the author's default (M1 MacBook, macOS 27.0.1). No
permission prompt appeared (author). Paths are shortened to `…/spikes/`.

| Candidate | `m01-out` (6 files) | `m03-empty` (empty) | cancel | where the dialog started (author) |
|---|---|---|---|---|
| A `electron.remote.dialog` | `…/spikes/m01-out` | `…/spikes/m03-empty` (twice) | `canceled=true paths=[]` (three times) | **Downloads, each time** |
| B `@electron/remote` | `…/spikes/m01-out` | `…/spikes/m03-empty` | `canceled=true paths=[]` | **Downloads, each time** |
| C input `webkitdirectory` | `files=6`; `file.path` is `undefined`; `webUtils.getPathForFile` gives the path of the first **file** (`…/m01-out/Combat cards.pdf`): the folder is that path cut at `webkitRelativePath`'s folder name | **`no file in the answer`: no path** | `cancelled` | the stored path, else Documents |
| D `showDirectoryPicker` | the name `m01-out` only | the name `m03-empty` only | **throws** `The user aborted a request` | the stored path, else Documents |

Odd: nothing reported. The console also holds Obsidian's own `[Violation] 'click' handler`
lines and the trace's long-task entries of the build (not the spike's).

**Reading by the rule written before the run:** **A** is the first candidate that answers an
absolute folder path for a folder with files and for the empty folder and reports a cancel
without an error; **B** does the same (the fallback). **C cannot give a path for an empty
folder** (and a new output folder is usually empty), so it is not used; **D gives a name, no
path**. The author preferred where C and D started the dialog; A and B started in
Downloads because the spike passed no start folder. **Unverified:** that A's and B's dialog
honours Electron's `defaultPath` option in Obsidian (documented by Electron, not measured
here): measured in M04. **Not established:** how long `electron.remote` stays available in
later Obsidian versions (measured for 1.15.0 only), which is why the story keeps B as a
fallback and a text field that always works.
