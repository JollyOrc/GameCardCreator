# M04 — The settings screen in Obsidian (US-007 AC-13)

Part of the [manual checks](../manual-checks.md).

**When:** after the code of US-007 (ticket #19), on a test build; and after any change to the
tab, the store or the folder dialog.

**Needs:** Obsidian desktop (the author's default environment unless stated), the scratch vault
with the test build installed. Prepared by the developer (SCAR-012, SCAR-018, SCAR-019): the
build installed with the checksums of the installed files equal to the fresh build's
(hand-over note); the plugin's `data.json` as written for M01 (kind rules `Skills` → skill and
`Spells` → spell, an output folder outside the vault) and its backup `spikes/data.json.m01.bak`
with a checksum, to restore after the check; a checksum list of the vault taken **before**; the
folders to pick (`spikes/m01-out`, `spikes/m03-empty`); the settings read where the check runs
and compared with what the steps assume. Restart Obsidian once so the build is loaded. The
developer waits for the tester's "go" after each block of steps.

**Expected version:** the version in the hand-over note (the plugin's entry in Community
plugins). If it differs, stop: the wrong build is installed.

**Run on a tab that stays open (SCAR-016):** do not close the settings between the blocks
unless a step says so.

**Decided before the run (SCAR-032):** the dialog's start folder (step 9) is a finding either
way: if it starts in the stored folder, AC-5 holds; if it starts elsewhere (Downloads), the
result is recorded and the story is amended, not hidden. Other steps pass or fail as written.

## Steps

1. **The tab.** Settings, Game Card Creator: the main page shows the status line, the output
   folder (a text field and a `Choose folder…` button), the kind rules with `Add rule`, and
   links to `Note properties` and `Page and text size`. The status line reads `Ready: 2 kind
   rules, output folder <the stored folder>`. Report the wording you see.
2. **Back and forth.** Open each sub page and use `Back`. Report anything that is missing, in
   the wrong place or ugly.
3. **A valid number.** On `Page and text size` set the margin to 15 and press **Enter**. Then
   set the gap to 2 and click **elsewhere** (a blur). Report whether each was kept after you
   leave the page and come back. The line under the sheet fields should say `4 cards per A4
   page (2 × 2)` (check it against the sizes).
4. **An invalid number.** Type 60 in the margin and press Enter: **red text under the field**
   with the message of the check, and the old value still saved after you leave and come back.
   Type `abc`: the message says it is not a number.
5. **Keyboard only.** Do steps 3 and 4 again without the mouse (Tab, Enter, Shift+Tab).
6. **Kind rules.** Type `Sk` in a rule's folder field: the vault's folders are suggested. Set a
   folder that does not exist: an orange or visible warning, and it is kept. Add a rule with an
   empty folder: refused (red). Add a rule with a folder that another rule has: refused.
   Delete a rule: it goes at once, no question; add it again.
7. **The status line follows.** Empty the output folder text: the status line says `Not ready:`
   with the reason; set it back.
8. **A folder inside the vault** as the output folder is accepted with no warning.
9. **The folder dialog.** Click `Choose folder…`: report **where the dialog starts** (the
   stored folder, Documents, Downloads?). Choose `spikes/m03-empty`: the field and the status
   line follow. Open it again and cancel: nothing changes. If the button is not shown, say so.
10. **Reset.** On `Note properties` change two names, then `Reset this page to defaults`: the
    question names the page and the focus is on `Cancel`; Escape and Enter do nothing; click
    `Reset`: only that page's values go back. Report that the main page has no reset.
11. **The file, on disk.** The developer reads `data.json` and the plugin folder after your
    steps: the backup `data-before-settings-screen.json` exists once and equals the file as it
    was before the first commit; the file holds your changes and the keys the screen does not
    know. Report nothing here; this is read from the disk.
12. **A hand edit while the tab is open.** With the tab open on a sub page, edit `data.json`
    by hand (change the output folder to another valid path), save it, return to the tab and
    commit a different field: **the hand edit must still be in the file** afterwards (the
    developer reads it). Report what the page showed after the edit.
13. **A refused run.** Empty the kind rules and run `Create cards from this deck note`: the
    notice names the problem and ends `See Settings → Game Card Creator (file: …)`.
14. **A run with the new settings.** Restore valid settings: the margin at 15 and the gap
    back at 0, and run the deck command: the PDF has 2 columns and 3 rows of cards per page
    (6 per page) and the same cards as in M01. Read it at reading size.
15. Is anything missing, odd or ugly that this list did not ask about? Report it even if it
    seems unrelated (SCAR-015): the labels, the wording, the layout, the errors.

**The developer's undo (SCAR-018):** `data.json` is restored from `spikes/data.json.m01.bak`
and its checksum checked; the backup file the screen made is kept until the check is closed,
then removed; the vault's checksum list is compared with the one taken before.
